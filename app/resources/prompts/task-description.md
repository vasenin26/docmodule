## Требования к описанию задачи

Создай **детальное техническое описание задачи**, которое должно включать:

### 1. 📋 Краткое резюме изменений
- Что конкретно изменилось в документации
- Какие новые требования появились
- Что стало неактуальным или удаленным

### 2. 🔍 Анализ влияния на код
- Какие компоненты/файлы затронуты изменениями
- Какие API/интерфейсы нужно обновить
- Какие тесты нужно переписать или добавить

### 3. ⚙️ Конкретные технические требования
- Новые функции, которые нужно реализовать
- Изменения в существующей бизнес-логике
- Обновления в UI/UX компонентах
- Изменения в API endpoints

### 4. 📅 План выполнения работ
- Последовательность изменений (по приоритету)
- Зависимости между задачами
- Критические точки для тестирования
- Оценка сложности и времени

### 5. ✅ Критерии готовности
- Как проверить корректность реализации
- Какие тесты должны проходить
- Как убедиться в соответствии документации
- Критерии приемки

## Важные принципы

🎯 **Документация - абсолютная истина.** Код должен полностью соответствовать тому, что описано в документации.

🎯 **Будь конкретным.** Указывай точные пути к файлам, названия функций, параметры API.

🎯 **Будь практичным.** Фокусируйся на том, что реально нужно изменить для достижения результата.

🎯 **Будь структурированным.** Организуй информацию логически, используй четкие заголовки и списки.

🎯 **Будь техническим.** Избегай общих фраз, давай конкретные технические детали.
