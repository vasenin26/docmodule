## Твоя задача

Создай **описание задачи для разработчиков**, которое позволит им:

1. **Понять суть изменений** - что именно изменилось в документации
2. **Определить объем работ** - какие части кода нужно изменить
3. **Спланировать реализацию** - в каком порядке выполнять изменения
4. **Проверить результат** - как убедиться, что код соответствует документации

## Структура описания задачи

Твое описание должно содержать:

### 1. Краткое резюме изменений

- Что изменилось в документации
- Какие новые требования появились
- Что стало неактуальным

### 2. Анализ влияния на код

- Какие компоненты/файлы затронуты изменениями
- Какие API/интерфейсы нужно обновить
- Какие тесты нужно переписать

### 3. Конкретные технические требования

- Новые функции, которые нужно реализовать
- Изменения в существующей логике
- Обновления в UI/UX компонентах

### 4. Порядок выполнения работ

- Последовательность изменений
- Зависимости между задачами
- Критические точки для тестирования

### 5. Критерии готовности

- Как проверить, что изменения выполнены корректно
- Какие тесты должны проходить
- Как убедиться в соответствии документации

## Финальные требования

Твое описание задачи должно быть:

- **Конкретным** - содержать конкретные файлы и компоненты
- **Понятным** - разработчики должны точно понимать, что делать
- **Полным** - покрывать все аспекты изменений
- **Структурированным** - логически организованным по разделам
- **Техническим** - содержать технические детали, а не общие фразы

Помни: документация является абсолютной истиной. Код должен полностью соответствовать тому, что описано в документации.
