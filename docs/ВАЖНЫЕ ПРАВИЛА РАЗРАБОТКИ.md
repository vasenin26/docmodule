# Работа со средой

Все зависимости приложения находятся в контейнере development.
Контейнеры объявлены в docker-compose.
Запускать команды php и npm необходимо в контейнере.
ВАЖНО! при запуске команды в контейнере обазательно нужно указывать пользователя local

Пример: docker compose exec -u local development ls

Проверку работы приложения и АПИ можно производить с помощью CURL.
Приложение доступно по адресу http://localhost:8000/

Пример: curl http://localhost:8000/

Используй Context7 для получения информации об используемых компонентах.

ВАЖНО! Избегай удаление данных из базы. Не выполняй команды который могут привести к потере данных.

# План работ

При составлении плана работ нужно придерживаться следующих правил:

* план работ составляется на основании описания задачи.
* план работ должен быть точным и подробным.
* план работ не должен содержать разночтения.
* в плане работ должны содержать пути к файлам требующим изменения.
* при написании плана работ никогда не добавлять в план работа описание функционала который не описан в задаче для которой составляется план работ.
* после написания плана работу необходимо проверить его на соответвие приавилам написания плана, при необходимости внести исправления.
* при внесении исправлений план необходимо проверить ешё раз и при необходимости внести исправления.
* если необходимо внести изменения в базу всегда требуй создания новой миграции.
* план работ нужно сохранять в папке plane в формате Markdown.

# Подоготовка плана работ на основе различия в ветках.

Для подготови плана работ на основании различия в ветках, необходимо получить различия между текущей git веткой и веткой main. Рекомендуется git --no-pager diff вывод без пагинации. На основе различия необходимо сформировать описание требуемых изменений необходимых для того, чтобы привести кодовую базу к состаянию удовлетворяющему новую версию документации. Описание требуемых изменений необходимо сформулировать в формате задачи для разработки. Описание задачи необходимо сохранить в папке tasks в формате Markdown.

# Документация

Проект содержит различные документации. 
Докумнтация хранятся в папке docs. 
Ни прикаких условиях нельзя обновлять файлы документации.
Документация являются абсолютной истиной, если поведение ситсемы не соответствует документации необходимо составить план работ для приведения системы в соответвие с инструкциями.
