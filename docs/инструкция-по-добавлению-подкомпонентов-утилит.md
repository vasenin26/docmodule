## Инструкция: добавление под‑компонентов для сообщений инструментов (`tool`)

Данный документ описывает, как добавлять новые под‑компоненты отображения для сообщений типа `tool` и подключать их в диспетчере `ToolMessage.vue` по полю `message.name`.

### 1) Структура и расположение файлов
- Диспетчер: `app/resources/js/components/AgentChat/messages/ToolMessage.vue` — выбирает под‑компонент по `message.name`.
- Папка под‑компонентов инструментов: `app/resources/js/components/AgentChat/messages/tools/`
- Именование под‑компонентов: `Tool<PascalCaseName>.vue`
  - Пример: для `message.name === 'get-task-list'` файл: `ToolGetTaskList.vue`

### 2) Контракт пропсов под‑компонентов
Каждый под‑компонент обязан принимать одинаковые пропсы:

```ts
defineProps<{
    message: LLMMessage;
    index: number;
}>()
```

Где `LLMMessage` — интерфейс из `app/resources/js/types/index.d.ts`.

### 3) Шаблон нового под‑компонента
Минимальный каркас файла `ToolXxx.vue`:

```vue
<script setup lang="ts">
import type { LLMMessage } from '@/types';

const props = defineProps<{ message: LLMMessage; index: number }>();

// Вспомогательные функции парсинга (если нужно):
function parseJson<T>(value?: string): T | undefined {
  if (!value) return undefined;
  try { return JSON.parse(value) as T; } catch { return undefined; }
}

// Пример: доступ к данным инструмента
// const name = (props.message.message as any)?.name;
// const result = parseJson<any>((props.message.message as any)?.result);
</script>

<template>
  <div class="rounded-lg p-3">
    <!-- Заголовок/иконка/лейбл статуса при необходимости -->
    <!-- Тело сообщения (результат работы инструмента) -->
  </div>
  <!-- Для длинных текстов используйте существующие композиции useTextExpansion/useMessageExpansion -->
  <!-- Не выводите HTML как v-html; только текст/разметка компонентов -->
  <!-- Ошибки парсинга обрабатывайте мягко (fallback) -->
  <!-- Не добавляйте побочных эффектов и сетевых запросов -->
  <!-- Стили и отступы придерживаются подхода в существующих компонентах сообщений -->
  
</template>
```

Рекомендации:
- Для длинных текстов используйте `useTextExpansion`/`useMessageExpansion` (см. соседние компоненты сообщений для примеров применения).
- Никаких консольных ошибок — при парсинге JSON используйте `try/catch` и fallback.
- Цветовая схема контейнера обычно совпадает с `ToolMessage.vue` (если нет явных требований).

### 4) Регистрация под‑компонента в диспетчере
В `ToolMessage.vue` существует маппинг `message.name → компонент`. Добавьте свою пару:

```ts
// Пример: toolComponentsMap["get-task-list"] = ToolGetTaskList
```

Правила выбора:
- Сравнение — строгое по строке `message.name`.
- Если соответствия нет — используется `ToolGeneric.vue` (дефолтный вывод).

### 5) Fallback‑поведение
- Если входные данные невалидны (например, `result` не парсится в ожидаемую структуру), компонент:
  - либо сам отображает осторожный fallback (краткий текст/пустое состояние),
  - либо отдаёт управление на общий `ToolGeneric.vue` (рекомендуется, если без валидных данных невозможно корректно отрендерить специальный формат).

### 6) Специальные иконки/лейблы статуса
- При необходимости повторно используйте разметку и классы иконок из `ServiceMessage.vue` (например, галочка успеха).
- Старайтесь не копировать большие блоки стилей; придерживайтесь текущих utility‑классов.

### 7) Тестирование
- Если есть тесты компонентов, добавьте проверку:
  - что при нужном `message.name` рендерится ваш под‑компонент;
  - корректное отображение данных (`title`, статусы и т. п.);
  - fallback при невалидных входных данных.

### 8) Примеры существующих под‑компонентов
- `ToolTasksComplete.vue` — специальный вывод результата для `tasks-complete`.
- `ToolGetTaskList.vue` — вывод списка задач для `get-task-list`.
- `ToolGeneric.vue` — дефолт для всех остальных инструментов.

Ориентируйтесь на их реализацию и соответствующие правила из техплана: `plane/2025-09-29-toolmessage-tasks-complete.md`.

### 9) Проверка качества
- Линтер без ошибок.
- Сборка проекта проходит.
- Визуально не нарушены другие типы сообщений (`user`, `assistant`, `system`, `service`, и т. д.).
