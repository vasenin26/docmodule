# Утилиты для LLM-агентов

Данный документ описывает рекомендуемые утилиты для расширения функциональности LLM-агентов при исследовании репозиториев и генерации технических планов.


### Базовые инструменты
- **`time`** - получение текущей даты и времени
- **`result`** - сохранение результата работы агента

### Git инструменты
- **`git-readFile`** - чтение содержимого файла из репозитория
- **`git-readDir`** - просмотр содержимого директории
- **`git-searchFileByName`** - поиск файлов по имени

### Анализ архитектуры проекта

#### `git-analyze-structure`
**Назначение**: Анализ структуры проекта и выявление паттернов архитектуры  
**Функции**: 
- Определение типа проекта (Laravel, React, Vue и т.д.)
- Выявление основных директорий
- Анализ конфигурационных файлов
- Определение точек входа в приложение

#### `git-get-dependencies`
**Назначение**: Анализ зависимостей проекта  
**Функции**:
- Чтение `composer.json`, `package.json`
- Анализ импортов и зависимостей
- Выявление версий используемых библиотек
- Определение потенциальных конфликтов

#### `git-find-config-files`
**Назначение**: Поиск и анализ конфигурационных файлов  
**Функции**:
- Поиск `.env.example`, `config/*`
- Анализ `webpack.config.js`, Docker файлов
- Определение настроек окружения
- Выявление параметров конфигурации

### Анализ кода и архитектурных паттернов

#### `git-search-pattern`
**Назначение**: Поиск кода по регулярным выражениям  
**Функции**:
- Поиск классов, методов, интерфейсов
- Выявление использования паттернов проектирования
- Поиск специфических конструкций кода
- Анализ стиля кодирования

#### `git-analyze-classes`
**Назначение**: Анализ классов и их связей  
**Функции**:
- Поиск наследования, интерфейсов, трейтов
- Анализ зависимостей между классами
- Определение архитектурных слоев
- Выявление нарушений принципов SOLID


## 📄 Утилиты для работы со страницами документации

### Анализ структуры и содержимого

#### `page-get-info`
**Назначение**: Получение полной информации о странице  
**Функции**:
- Загрузка метаданных страницы
- Получение содержимого и статуса
- Анализ связей с другими страницами
- Определение типа страницы (текущая/черновик/актуализированная)

#### `page-get-attached-files`
**Назначение**: Анализ прикрепленных файлов из репозиториев  
**Функции**:
- Получение списка прикрепленных файлов
- Загрузка содержимого файлов
- Анализ изменений в файлах
- Проверка актуальности ссылок

#### `page-get-hierarchy-tree`
**Назначение**: Построение дерева иерархии страниц  
**Функции**:
- Анализ родительско-дочерних связей
- Определение глубины вложенности
- Построение карты документации
- Выявление нарушений структуры

#### `page-find-related-pages`
**Назначение**: Поиск связанных страниц  
**Функции**:
- Анализ ссылок в содержимом
- Поиск общих прикрепленных файлов
- Выявление тематических связей
- Определение зависимостей между страницами

#### `page-analyze-dependencies`
**Назначение**: Анализ зависимостей между страницами  
**Функции**:
- Выявление влияния изменений одной страницы на другие
- Определение критически важных страниц
- Анализ каскадных эффектов
- Планирование порядка обновлений

#### `page-get-project-pages`
**Назначение**: Получение всех страниц проекта  
**Функции**:
- Анализ структуры документации проекта
- Оценка полноты покрытия
- Выявление пробелов в документации
- Группировка по иерархии

### Анализ актуализации и LLM интеграции

#### `page-get-actualization-info`
**Назначение**: Анализ процессов актуализации страницы  
**Функции**:
- Получение статуса актуализации
- Анализ истории обновлений
- Исследование связанных чатов LLM
- Оценка качества актуализации

#### `page-analyze-file-sync`
**Назначение**: Анализ синхронизации с файлами репозитория  
**Функции**:
- Проверка актуальности прикрепленных файлов
- Выявление расхождений между документацией и кодом
- Валидация URL-ссылок на файлы
- Определение необходимости обновления

#### `page-get-task-history`
**Назначение**: Анализ созданных задач для страницы  
**Функции**:
- История генерации задач и техпланов
- Анализ результативности задач
- Связь с LLM-контекстом
- Оценка качества генерации


## 🔧 Техническая реализация

Все утилиты реализуют интерфейс `ToolInterface` со следующими методами:

- `execute(array $args): ?string` - выполнение функции утилиты
- `getProps($name): array` - описание параметров для LLM

Утилиты регистрируются в `ToolsFactory` и включаются в `ToolServiceFactory` для предоставления LLM-агентам через интерфейс `LLMTools`.

## 📝 Примечания

- Все утилиты должны возвращать данные в JSON формате для удобства парсинга LLM
- Параметры должны быть четко описаны в `getProps()` методе
- Обработка ошибок должна возвращать понятные сообщения
- Утилиты должны быть оптимизированы по производительности
- Следует предусмотреть кэширование для часто используемых операций
